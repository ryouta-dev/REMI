# REMI — QR-заказы

Приложение рассчитано на отдельную базу MariaDB, PHP 8.3+ с расширениями pdo_mysql, mbstring, curl и GD с WebP, HTTPS и планировщик. В production PHP должен открывать `index.php` по адресу сайта. `index.html` остаётся входом для статического предпросмотра.

## Развёртывание

1. Подготовьте отдельную базу с кодировкой `utf8mb4`. Скопируйте `config.example.php` за пределы корня сайта как `remi-config.php` либо задайте путь в `REMI_CONFIG`. Создайте закрытый каталог `media_dir`, в который PHP может писать. Укажите конечный адрес HTTPS в `base_url`: на него будут вести печатные QR.
2. Разместите файлы приложения и нужные assets. Правила `.htaccess` должны загружать `index.php` и закрывать HTTP-доступ к `server/`. После развёртывания отдельно проверьте, что `/server/schema.sql` возвращает 403 или 404. Если хостинг отдаёт статику напрямую через nginx, запретите этот префикс и на уровне nginx.
3. Подготовьте базу, создайте первого администратора и импортируйте согласованный каталог один раз.

   ```sh
   php server/cli.php install
   php server/cli.php admin remi-admin
   php server/cli.php import menu.json
   ```

   Пароль передаётся через stdin или переменную `REMI_INITIAL_PASSWORD`. Инициализация оставляет приём выключенным, до включения сотрудником.
4. В поле `telegram_bot` укажите имя бота без `@`, в `telegram_chat` — числовой ID рабочего чата, в `telegram_token` — токен BotFather, в `telegram_secret` — случайный секрет вебхука на 32–256 символов из букв, цифр, дефиса и подчёркивания. Добавьте бота в рабочий чат с правом отправлять сообщения и запустите `php server/cli.php webhook`. Сотрудники привязывают аккаунты по ссылкам из панели. Команда `/remi` открывает переключатель приёма, `/orders` показывает последние заказы открытых столиков, `/order 123` открывает карточку заказа по номеру. Это работает и для заказов, обработанных на сайте во время сбоя Telegram.
5. В планировщике запустите `php /absolute/path/server/cli.php notify` каждую минуту. Если FastCGI позволяет, PHP пробует отправить уведомление сразу после ответа гостю, а планировщик подбирает отложенные попытки. В базе сохраняются исходный заказ и сведения о доставке. Telegram может повторно показать уведомление, если принял его, но не вернул ответ серверу. В таком случае оба сообщения относятся к одному номеру заказа.
6. Настройте ежедневный дамп MariaDB в планировщике: `sh /absolute/path/server/backup.sh /private/mysql-client.cnf DATABASE /private/backups`. В файле клиента с правами 0600 в секции `[client]` укажите `host`, `user` и `password`. Заранее создайте закрытый каталог для копий. Если на хостинге утилита называется `mysqldump`, задайте `REMI_DUMP=mysqldump`. Настройте срок хранения и копирование за пределы хостинга. Для проверки распакуйте копию и импортируйте её в пустую тестовую БД. Каталог `media_dir` резервируется отдельно, вместе с опубликованными assets.
7. На `/staff.html` добавьте столики, скачайте SVG QR и проверьте их с телефонов. Запустите пробную смену с закрытием столика и дозаказом, отключением Telegram, сменой цены и стоп-листом.

## Импорт каталога

Импорт создаёт идентификаторы в пустой базе. Старый формат `prices` поддерживается: одна цена становится одним вариантом, объёмы вида `(300/400 мл)` берутся из названия. Позиции с несколькими ценами без подписей можно просматривать, а заказать их можно после проверки порций, заполнения подписей и включения вариантов в админке.

Для подтверждённых вариантов можно передать `"variants": [{"label": "300 мл", "price": 890, "available": true}]` вместо `prices`. Поле `image` содержит путь относительно `assets/` без суффикса ширины, как в исходной витрине. Данные меню и файлы изображений согласуются перед публикацией.

## Локальная проверка

Подготовьте отдельную тестовую базу и настройте `base_url` на `http://127.0.0.1:8080`. Запустите `php -S 127.0.0.1:8080 server/local-router.php` из корня проекта. Для проверки одновременных запросов можно поднять второй PHP-процесс на другом локальном порту с той же тестовой БД.

Гость опознаётся по случайному cookie, действующему сутки с момента последнего обращения к заказам. Админские сессии отдельны от привязки Telegram, а сброс пароля завершает предыдущие входы сотрудника на сайте. Пароль хранится в виде хеша. После отключения сотрудника уберите его и из рабочего Telegram-чата, если ему больше нельзя читать сообщения в группе.
